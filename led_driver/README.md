# led_driver

[English version](README_EN.md)

ROS 2-драйвер адресной светодиодной ленты. Нода общается по Serial с платой (Arduino Nano или ESP32), на которой стоит прошивка [`led_controller_arduino`](../led_controller_arduino/README.md), и даёт управлять режимом и яркостью ленты через топики.

Спецификация протокола обмена с платой — в [глобальном README](../README.md#протокол-управления-светодиодной-лентой).

## Возможности

- Переключение режимов ленты по названию или номеру.
- Изменение яркости в диапазоне 0–255.
- Публикация фактического состояния ленты в latched-топиках: подписчик сразу получает последнее значение.
- Подтверждение каждой команды платой и автоматический повтор при сбое связи.
- Класс протокола `LedSelectorLink`, не зависящий от ROS: его можно использовать в обычных скриптах.

## Узел `led_driver`

Запускается исполняемым файлом `led_driver`. При старте открывает порт и ждёт загрузки платы до 3 с, потом публикует её стартовое состояние. Если плата не прислала его сама, нода запрашивает `STATUS`.

Публикуется только состояние, подтверждённое платой ответом `OK`. Если команда не прошла, топики состояния не меняются.

### Параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `port` | string | `/dev/ttyUSB0` | Последовательный порт платы |
| `baud` | int | `115200` | Скорость порта. Должна совпадать с `BAUD` в прошивке |
| `brightness` | int | `-1` | Яркость, которую нода выставит при запуске. `-1` — оставить как есть |

### Подписки

| Топик | Тип | Описание |
|-------|-----|----------|
| `/led_driver/mode` | `std_msgs/String` | Название режима (`rainbow`, `dot`, `azure`, `green`, `orange`, `off`; регистр не важен) или его номер `1`–`6` |
| `/led_driver/brightness` | `std_msgs/UInt8` | Яркость 0–255 |

### Публикации

| Топик | Тип | QoS | Описание |
|-------|-----|-----|----------|
| `/led_driver/status` | `std_msgs/String` | TRANSIENT_LOCAL, depth 1 | Текущий режим, например `GREEN` |
| `/led_driver/brightness_state` | `std_msgs/UInt8` | TRANSIENT_LOCAL, depth 1 | Текущая яркость |

Чтобы получить последнее значение при подписке, подписчик тоже должен использовать `TRANSIENT_LOCAL` (см. «Полезные проверки»).

### Режимы

| № | Название | Поведение |
|---|----------|-----------|
| 1 | `rainbow` | Бегущая радуга |
| 2 | `dot` | Зелёная точка с хвостом бежит по кругу |
| 3 | `azure` | Бирюзово-лазурный, светодиоды загораются по очереди |
| 4 | `green` | Зелёный, светодиоды загораются по очереди |
| 5 | `orange` | Оранжевый, вся лента сразу |
| 6 | `off` | Лента погашена |

Список режимов задан в кортеже `MODES` в `led_driver/led_driver.py`. Он должен совпадать по составу и порядку с массивом `MODE_NAMES` в прошивке.

### Обработка ошибок

- Неизвестный режим нода отбрасывает сама: на плату ничего не уходит, в лог пишется предупреждение со списком доступных режимов.
- Если плата не ответила `OK` за 0,5 с, команда повторяется, всего до 3 попыток. После этого в лог пишется ошибка.
- Если порт не открылся при запуске, нода завершается с исключением.
- Если порт пропал во время работы (например, вынули кабель), ошибка пишется в лог не чаще раза в 5 с. Автоматического переподключения нет: подключите плату и перезапустите ноду.

## Использование без ROS

Класс `LedSelectorLink` реализует протокол и не импортирует ROS:

```python
from led_driver.led_driver import LedSelectorLink

link = LedSelectorLink('/dev/ttyUSB0')
print(link.open())                 # ('RAINBOW', 80) — стартовое состояние
print(link.set_mode('green'))      # (True, 'GREEN', 80)
print(link.set_mode(2))            # (True, 'DOT', 80)
print(link.set_brightness(150))    # (True, 'DOT', 150)
print(link.status())               # (True, 'DOT', 150)
link.close()
```

Каждая команда возвращает `(ok, режим, яркость)`. При неудаче — `(False, текст ошибки, None)`, где текст — последний ответ платы (`ERR ...`) или `TIMEOUT`.

| Аргумент конструктора | По умолчанию | Описание |
|-----------------------|--------------|----------|
| `port` | — | Последовательный порт |
| `baud` | `115200` | Скорость порта |
| `timeout` | `0.5` | Время ожидания ответа на одну попытку, с |
| `retries` | `3` | Количество попыток |
| `logger` | `None` | Логгер с методом `warn` (например, логгер ROS-ноды) |

## Запуск

```bash
ros2 run led_driver led_driver --ros-args -p port:=/dev/ttyUSB0
ros2 run led_driver led_driver --ros-args -p port:=/dev/ttyUSB0 -p brightness:=60
```

Доступ к порту без `sudo` даёт группа `dialout`:

```bash
sudo usermod -aG dialout $USER    # затем перелогиниться
```

Arduino Nano (особенно клоны с CH340) обычно появляется как `/dev/ttyUSB0`, ESP32 — как `/dev/ttyUSB0` или `/dev/ttyACM0`. Если к компьютеру подключено несколько устройств, надёжнее указывать постоянное имя из `/dev/serial/by-id/`.

## Полезные проверки

```bash
# Какие порты есть
ls /dev/ttyUSB* /dev/ttyACM* /dev/serial/by-id/

# Переключить режим
ros2 topic pub --once /led_driver/mode std_msgs/msg/String "{data: azure}"
ros2 topic pub --once /led_driver/mode std_msgs/msg/String "{data: '2'}"

# Изменить яркость
ros2 topic pub --once /led_driver/brightness std_msgs/msg/UInt8 "{data: 150}"

# Текущее состояние (latched)
ros2 topic echo --qos-durability transient_local /led_driver/status
ros2 topic echo --qos-durability transient_local /led_driver/brightness_state
```

Если нода не может связаться с платой, проверьте плату без ROS: откройте Serial Monitor в Arduino IDE на скорости 115200 и отправьте `STATUS`. Порт при этом должен быть свободен: остановите ноду.
