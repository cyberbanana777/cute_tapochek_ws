# cute_tapochek

[English version](README_EN.md)

Интерактивный робот на базе манипулятора SO-ARM101. Робот проигрывает движения, заранее записанные с leader-руки, и показывает своё состояние адресной светодиодной лентой.

Репозиторий — набор пакетов ROS 2 и прошивка для микроконтроллера. Bringup самих рук (ros2_control, контроллеры, телеуправление) живёт в отдельном репозитории `soarm101` и сюда не входит.

## Состав репозитория

| Каталог | Тип | Назначение |
|---------|-----|------------|
| [`cute_tapochek_interfaces`](cute_tapochek_interfaces/README.md) | ROS 2, ament_cmake | Action, сервисы и сообщения подсистемы движений |
| [`cute_tapochek_motion`](cute_tapochek_motion/README.md) | ROS 2, ament_python | Нода `motion_server`: библиотека движений, запись с leader, проигрывание на follower |
| [`cute_tapochek_gui`](cute_tapochek_gui/README.md) | ROS 2, ament_python | rqt-плагин «Motion Studio» для записи и проигрывания движений |
| [`led_driver`](led_driver/README.md) | ROS 2, ament_python | ROS 2-драйвер светодиодной ленты: топики → команды по Serial |
| [`led_controller_arduino`](led_controller_arduino/README.md) | Arduino-скетч | Прошивка Arduino Nano / ESP32, управляющая лентой WS2812B |
| `motions/` | данные | Библиотека движений: по CSV-файлу на движение, хранится в git |
| `text_to_voice/` | — | Голос робота, в разработке |

## Архитектура

```
 leader-рука ──/leader/joint_states──┐
                                     ▼
 Motion Studio (rqt) ──сервисы──► motion_server ──FollowJointTrajectory──► follower-рука
 автомат поведения  ──/play_motion─┘    │   └────GripperCommand──────────► схват
                                        │
                                        └──/arm_relay/set_enabled──► телеуправление (soarm101)
                                            /gripper_relay/set_enabled

 любой узел ──/led_driver/mode, /brightness──► led_driver ══USB Serial══► плата ──► лента WS2812B
```

- `motion_server` владеет библиотекой движений. Все действия с ней (запись, сохранение, проигрывание, удаление) выполняются через его сервисы и action, поэтому GUI, терминал и автомат поведения работают одинаково.
- `led_driver` — тонкий мост между ROS 2 и прошивкой ленты. Логика эффектов целиком живёт на микроконтроллере, компьютер только выбирает режим и яркость.

## Требования

- Ubuntu 22.04, ROS 2 Humble.
- Репозиторий `soarm101` с патчем `soarm101_teleop_pause.patch` (сервис паузы `~/set_enabled` у `arm_relay` и `gripper_relay`) и `open_loop_control: true` у `joint_trajectory_controller` в `real_controllers.yaml`.
- `python3-serial` для `led_driver`.
- Arduino IDE или `arduino-cli` и библиотека FastLED для прошивки ленты.

## Сборка

```bash
cd ~/cute_ws
rosdep install --from-paths src --ignore-src -y
colcon build --symlink-install
source install/setup.bash
rqt --force-discover    # один раз после первой сборки, чтобы rqt увидел Motion Studio
```

`--symlink-install` нужен, чтобы `motion_server.launch.py` сам нашёл папку `motions/` в исходниках. Подробности — в [README `cute_tapochek_motion`](cute_tapochek_motion/README.md).

Каталог `led_controller_arduino` colcon пропускает (в нём нет `package.xml`). Прошивка собирается отдельно, см. [её README](led_controller_arduino/README.md).

## Быстрый старт

**Движения:**

```bash
# терминал 1: руки и телеуправление
ros2 launch soarm101_teleoperate teleoperate.launch.py
# терминал 2: сервер движений
ros2 launch cute_tapochek_motion motion_server.launch.py
# терминал 3: GUI
ros2 run cute_tapochek_gui motion_studio
```

Проигрывание из кода или терминала:

```bash
ros2 action send_goal /play_motion cute_tapochek_interfaces/action/PlayMotion "{name: ahe}" --feedback
```

**Лента:**

```bash
ros2 run led_driver led_driver --ros-args -p port:=/dev/ttyUSB0
ros2 topic pub --once /led_driver/mode std_msgs/msg/String "{data: green}"
ros2 topic pub --once /led_driver/brightness std_msgs/msg/UInt8 "{data: 150}"
```

## Протокол управления светодиодной лентой

Протокол связывает `led_driver` (хост) и прошивку `led_controller_arduino` (устройство). Он текстовый и построчный, поэтому плату можно проверить вручную из любого терминала, например из Serial Monitor в Arduino IDE.

### Физический уровень

| Параметр | Значение |
|----------|----------|
| Интерфейс | UART через USB (виртуальный COM-порт платы) |
| Скорость | 115200 бод (`BAUD` в прошивке, параметр `baud` в `led_driver`) |
| Формат кадра | 8N1 |
| Кодировка | ASCII |

### Кадрирование команд

- Команда заканчивается символом `\n` или `\r`; `\r\n` тоже подходит.
- Если перевода строки нет, команда считается законченной через 50 мс тишины после последнего байта (`LINE_TIMEOUT_MS`). Поэтому работает любая настройка «окончания строки» в Serial Monitor.
- Перед разбором плата удаляет из команды все пробелы и переводит её в верхний регистр: `bright 120`, `BRIGHT 120` и `Bright120` равнозначны.
- Учитываются первые 15 значимых символов, остальные молча отбрасываются.
- Пустая строка игнорируется: на неё плата не отвечает. Хост использует её как «будильник» (см. «Надёжность доставки»).

### Команды

| Команда | Пример | Действие |
|---------|--------|----------|
| `<НАЗВАНИЕ>` | `GREEN` | Включить режим по названию |
| `<НОМЕР>` | `4` | Включить режим по номеру: одна цифра `1`–`6` |
| `BRIGHT <0-255>` | `BRIGHT 120` | Установить яркость. Пробел после `BRIGHT` не обязателен |
| `STATUS` | `STATUS` | Запросить текущее состояние, ничего не меняя |

Включение режима всегда перезапускает эффект с чистой ленты, даже если этот режим уже активен: например, `GREEN` ещё раз заново «зажжёт» светодиоды по очереди. Смена яркости эффект не перезапускает.

### Режимы

| № | Название | Поведение |
|---|----------|-----------|
| 1 | `RAINBOW` | Бегущая радуга |
| 2 | `DOT` | Зелёная точка с затухающим хвостом бежит по кругу: после последнего светодиода возвращается на первый |
| 3 | `AZURE` | Светодиоды по очереди загораются бирюзово-лазурным, затем лента горит статично |
| 4 | `GREEN` | То же, зелёным |
| 5 | `ORANGE` | Вся лента сразу загорается оранжевым |
| 6 | `OFF` | Лента гаснет |

Номер режима — это его позиция в массиве `MODE_NAMES` прошивки плюс один. Порядок режимов в прошивке и в кортеже `MODES` в `led_driver` должен совпадать.

### Ответы

Каждая строка ответа заканчивается `\r\n`. Хост обязан игнорировать любые строки, которые не начинаются с `OK` или `ERR`: это справка и служебные сообщения.

| Ответ | Когда | Пример |
|-------|-------|--------|
| `OK <РЕЖИМ> <ЯРКОСТЬ>` | Любая успешная команда, включая `STATUS` | `OK GREEN 120` |
| `ERR <команда>` | Команда не распознана или значение неверно. В ответе — команда после нормализации (без пробелов, в верхнем регистре) | `ERR BRIGHT300` |

Ответ `OK` всегда содержит полное фактическое состояние устройства, поэтому хосту не нужно хранить его у себя.

После `ERR` на неизвестный режим или команду плата дополнительно печатает справку (блок строк, см. ниже). После `ERR` на неверную яркость справки нет.

Типичные ошибки:

| Запрос | Ответ | Причина |
|--------|-------|---------|
| `PURPLE` | `ERR PURPLE` + справка | Нет такого режима |
| `7` | `ERR 7` + справка | Номер вне диапазона |
| `BRIGHT 300` | `ERR BRIGHT300` | Значение больше 255 |
| `BRIGHT` | `ERR BRIGHT` | Нет значения |

### Запуск устройства

После сброса плата печатает:

```
READY
Режимы:
  1 / RAINBOW
  2 / DOT
  3 / AZURE
  4 / GREEN
  5 / ORANGE
  6 / OFF
  BRIGHT <0-255>, STATUS
OK RAINBOW 80
```

Последняя строка — стартовое состояние: режим `RAINBOW`, яркость `BRIGHTNESS` из прошивки (80). Состояние не сохраняется между перезагрузками.

Открытие порта сбрасывает Arduino Nano (и часто ESP32) через линию DTR. Поэтому хост после открытия порта должен подождать загрузки: `led_driver` ждёт строку `OK` до 3 с, а если её не было — посылает `STATUS`.

### Надёжность доставки

На Arduino Nano вывод на ленту (`FastLED.show()`) на время передачи данных выключает прерывания. Байты UART, пришедшие в этот момент, теряются. Протокол решает это с двух сторон.

**Устройство** не обновляет ленту, пока идёт приём, и ещё 30 мс после последнего принятого байта (`QUIET_MS`).

**Хост** отправляет каждую команду так:

1. Очищает входной буфер.
2. Отправляет пустую строку `\n`. Она переводит плату в «тихий» режим, а заодно выталкивает возможный мусор из её буфера.
3. Ждёт 5 мс и отправляет команду с `\n`.
4. Ждёт строку `OK` или `ERR` до 0,5 с, пропуская остальные строки.
5. Если пришло не `OK`, повторяет шаги 1–4, всего до 3 попыток.

Все команды идемпотентны, поэтому повтор безопасен: в худшем случае эффект перезапустится ещё раз.

### Пример сеанса

```
→ 3
← OK AZURE 80
→ BRIGHT 150
← OK AZURE 150
→ dot
← OK DOT 150
→ STATUS
← OK DOT 150
→ PURPLE
← ERR PURPLE
← Режимы:
← ...
```

## Формат движений

Каждое движение — отдельный файл `motions/<имя>.csv`: время в секундах, позиции суставов в радианах, метаданные в строках с `#`. Имя файла — это имя движения. Подробное описание формата — в [README `cute_tapochek_motion`](cute_tapochek_motion/README.md#формат-файла-движения).
